QoQ Payment Track Record — Chart Variants
6 reference patterns from real products. Same data, different visual languages. Pick one to build into the drawer.
Variant 1
DPD Dot Grid  CIBIL / Experian style
One colored cell per month. 12 months across, one row per buyer account. Green = on time, yellow/orange/red = days past due, dark red = default. The full year's payment texture is visible in a single glance — you don't read it, you feel it.

Variant 3
Line + Area Trend  Mixpanel / Amplitude / Google Analytics style
On-time % plotted as a line over quarters, with a green/red area fill below. The slope of the line is the story — flat is fine, dropping is alarming. Benchmark line (e.g. platform avg 78%) gives instant comparison context.
Seen in:
Mixpanel Retention
Amplitude Charts
Stripe Dashboard
K C India — flat, healthy
Reliance — sharp decline
Best for: Showing trend direction — the slope of the line is immediately readable. Benchmark line adds comparative context without another dataset. Trade-off: Doesn't show the composition of failures (defaults vs outside TREDS vs other delays). You see that it dropped, not what drove it.
Variant 4
Lollipop / Dot Plot  The Economist / FT style
Each quarter = one dot positioned at the on-time %. A thin line connects them to a baseline. Cleaner than a bar chart because you're comparing a single value per period — no segment noise. Color of dot = tier (green/amber/red). Dashed line = benchmark.
Seen in:
The Economist Data
Financial Times Charts
Our World in Data
K C India — consistent high
Reliance — falling dots
Best for: Clean, minimal. The falling dots are visually very readable. Great when you need to show 6–8 periods and don't want the chart to feel heavy. Trade-off: Same as line chart — no composition breakdown.
Variant 5
Calendar Heatmap  GitHub Activity / WakaTime style
Each cell = one invoice. Arranged in a grid of weeks (columns) × slots (rows). Green shades = paid on time, red = default, orange = outside TREDS, yellow = late. At a glance you see the density and cluster of problems. A cluster of red = a bad patch; isolated dots = one-offs.

Best for: Invoice-level history. You can see if problems cluster in one quarter or are spread across the year. Trade-off: Needs invoice-level data (one cell = one invoice). With only QoQ totals, you'd need to approximate. Also gets wide if you show 12 months × 5 invoices/week.
Variant 6
Horizontal Bullet Chart  SAP Analytics / Stephen Few style
Each quarter = one horizontal bar. The bar length = on-time %. Background zones mark good/fair/poor ranges. A vertical tick marks the benchmark (platform avg). Lets you compare all 4 quarters on a shared axis at once — no scrolling, no stacking.

Decision guide
Which one to pick?
Variant Shows composition? Shows trend? Data needed Drawer fits?
1 · DPD Dot Grid ✓ per month ✓ pattern visible Monthly DPD per invoice ✓ compact
2 · Stacked Bar (current) ✓ all 4 types ~ harder to read QoQ totals ✓ ✓
3 · Line / Area ✗ on-time % only ✓ clearest slope QoQ totals ✓ ✓
4 · Lollipop / Dot ✗ on-time % only ✓ clean & minimal QoQ totals ✓ ✓ most compact
5 · Heatmap ✓ per invoice ✓ cluster pattern Invoice-level dates needed ~ can be wide
6 · Bullet Chart ✗ on-time % only ✓ benchmark context QoQ totals ✓ ~ 4 rows = tall
Recommendation: Combine 3 (Line chart — shows trend clearly) with the existing breakdown cards (defaults + outside TREDS count). Line = where is it going. Cards = what drove it. Together they answer both questions.
